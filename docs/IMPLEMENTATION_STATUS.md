# Implementation status

Status verified on 2026-11-05 against development branch commit 5bf1e754916ccddde1d9be64014189865fd3d99e. This is an MVP in active development, not a production-ready release.

| Area | Status | Verified implementation and remaining gaps |
| --- | --- | --- |
| Authentication | Partial | Better Auth registration, login, session and logout have HTTP integration coverage. Optional Resend delivery now supports verification and password reset flows with generic reset responses and session revocation; provider delivery has only mock tests locally. No provider credentials or sender domain are configured. Rate limits and session-expiry UX remain. |
| Organizations and membership | Partial | Authenticated organization create/list and membership-scoped access. Owner/admin company name, GSTIN format and pre-ledger fiscal-year settings are editable with transactional membership fencing and audit. Team APIs/UI now list and invite registered verified users, accept only as the invited identity, change roles and suspend/reactivate members with audit events. When the optional Resend provider is configured, invitation notifications are sent after the membership transaction; send failure leaves a pending invitation and is reported to the owner. Without provider configuration, share instructions manually. Ownership transfer and persistent switching remain. Membership DB integration tests require CI because local MongoDB is unavailable. |
| Chart of accounts | Partial | Tenant-scoped list/create/rename/archive API, responsive UI, membership write fence, audit, first-post serialization and legacy journal reference protection. Optional idempotent 23-account INR starter chart and explicit one-time balanced opening-balance journal are implemented; account grouping/normal balance metadata remain. |
| Journals | Partial | Authenticated tenant-scoped list/detail, manual posting and reversal endpoints; actor from session, role fences, idempotency, audit and fiscal period gate. MUI review-before-post workflow and reversal reason. Opening balances post through a separately audited source journal. General ledger aggregation, drafts and accounting exports remain. |
| Fiscal periods | Foundation implemented | Annual periods default to April–March; dates use Asia/Kolkata; first use creates the open period transactionally; owner/admin close is fenced and audited; both journal posting and reversal reject a closed current period. Owner/admin close now requires an explicit confirmation after a server-recomputed checklist: posted journal debits/credits must balance and imported bank entries must be reconciled. Draft invoices/bills are visible nonblocking review reminders. The close increments the posting fence transactionally and writes an audit event. No period reopening policy. |
| Contacts | Partial | Tenant-scoped customer/vendor create, list, search, detail read, edit and archive with roles, audit and duplicate protection; default list size is 50 with cursor paging. Phone, validated optional GSTIN and billing address are captured and editable. Organization identifiers, opening balances, exports and customer/vendor ledgers remain. |
| Products and services | Partial | Tenant-scoped catalog API and responsive create/search UI; safe integer paise, unique organization code, audit and archive. Optional HSN/SAC and tax category/rate metadata are captured with explicit user entry; no rate table or code verification is provided. Units and edit UI remain. |
| Sales invoices | Partial | Service drafts snapshot customer/service facts and optional due date; issuance assigns an India fiscal-year number and atomically posts AR against sales income with audit/idempotency. Due balances accept partial receipts and partial credit notes; each credit note atomically reduces sales income and AR, is immutable, audited and idempotent, and cannot exceed the unpaid balance. Draft invoices can now store taxable value, CGST/SGST/IGST integer-paise components, price-inclusive/exclusive basis and a supplied place-of-supply code/classification. Tax-bearing posting is explicitly blocked pending qualified review. Discounts, inventory/COGS and richer PDF templates remain. |
| Purchases and expenses | Partial | Vendor bill drafts validate active same-tenant vendors and expense accounts; posting is human-confirmed, idempotent and atomic with immutable bill facts, audit, and expense debit/payables credit. Vendor payments support partial/final allocation. Vendor credit notes debit AP and credit the selected expense account, are immutable/audited/idempotent, cannot exceed unpaid bill balances, and adjust later payment eligibility. Tax/inventory bills and attachments remain. |
| Receipts, payments and banking | Partial | Customer receipts and vendor payments can be allocated partially or fully to issued invoices/posted bills with cash/bank accounts, outstanding-balance checks, tenant/role fences, idempotency, audit and atomic control-account journals. Credit notes reduce both receivable and payable subledgers and reconcile to their documents; they are not cash refunds. Bank statements now support signed integer-paise CSV imports with duplicate fingerprints, journal matching without implicit posting, and audited reconciliation guarded by opening/closing ledger balances, unmatched-line checks and non-overlapping periods. Web Banking workflow is connected and mobile-width E2E verified. Advances, refunds and transfers remain. |
| General ledger and reports | Partial | Tenant-scoped general ledger with India-local date filters, normal-side running balance and cursor pagination; trial balance reconciles debit/credit; fiscal-year P&L and balance sheet include current earnings. Aged receivables/payables summarize outstanding amounts in date buckets and exclude settled documents. Accounts-receivable and accounts-payable control balances are compared against open invoice/bill balances with difference indicators. Formula-safe CSV exports cover trial balance, P&L, balance sheet, aging and full cursor-paginated ledger rows with opening balance. A date-filtered dashboard now derives revenue/expenses from period journals and cash, receivables, payables from ledger balances through the end date, and shows recent posted activity. First Mongo CI run caught a cash-fixture account-code mismatch; fixture is corrected locally but awaits CI rerun. Full ledger export now walks every cursor page using the server-scoped date and tenant filters. |
| GST | Foundation partial | Product HSN/SAC, tax category and manually supplied rate; invoice draft supply classification, place-of-supply code and per-line/aggregate tax-component snapshots; integer-paise inclusive/exclusive calculator with half-up rounding tests. Tax-bearing invoices cannot be issued/posted. A GST setup review screen lists user-entered HSN/SAC, category and rate data with explicit verification limits. Rate/HSN validation, GSTIN checksum, discounts/credit-note tax handling, reverse charge, export/SEZ, official rate data and expert review remain. No compliance claim. |
| AI assistance | Missing | No draft/explain/review workflow. Any future AI must require explicit human approval before posting. |
| Browser/mobile | Partial | Responsive web shell and auth/onboarding, dashboard, account, opening balance, contact, product, invoice, receipt, bill, payment and bank workflows. Playwright covers sign-up, financial vertical slices and bank import/matching/reconciliation at 390px; contact edit, dashboard, and fiscal close checklist assertions are added but await execution against an available local API/database. There is no mobile app workspace. |
| Release operations | Missing | No verified staging, production monitoring, least-privilege runtime database role, backup/restore rehearsal or release checklist. |
