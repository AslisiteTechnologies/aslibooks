# Implementation status

Status verified on 2026-11-04 from the local checkout `develop/phase-1-foundation`. This is an MVP in active development, not a production-ready release.

| Area | Status | Verified implementation and remaining gaps |
| --- | --- | --- |
| Authentication | Partial | Better Auth registration, login, session and logout have HTTP integration coverage. Password recovery, verified-email delivery, rate limits and session-expiry UX remain. |
| Organizations and membership | Partial | Authenticated organization create/list and membership-scoped access. Owner/admin company name, GSTIN format and pre-ledger fiscal-year settings are editable with transactional membership fencing and audit. Team APIs/UI now list and invite registered verified users, accept only as the invited identity, change roles and suspend/reactivate members with audit events. Invitations are not emailed; the owner must tell the invitee to sign in. Email verification delivery is not configured, so new users cannot currently satisfy the verified-user invitation requirement through the shipped UI. Ownership transfer and persistent switching remain. Membership DB integration tests are pending CI because local MongoDB is unavailable. |
| Chart of accounts | Partial | Tenant-scoped list/create/rename/archive API, responsive UI, membership write fence, audit, first-post serialization and legacy journal reference protection. Optional idempotent 23-account INR starter chart and explicit one-time balanced opening-balance journal are implemented; account grouping/normal balance metadata remain. |
| Journals | Partial | Authenticated tenant-scoped list/detail, manual posting and reversal endpoints; actor from session, role fences, idempotency, audit and fiscal period gate. MUI review-before-post workflow and reversal reason. Opening balances post through a separately audited source journal. General ledger aggregation, drafts and accounting exports remain. |
| Fiscal periods | Foundation implemented | Annual periods default to April–March; dates use Asia/Kolkata; first use creates the open period transactionally; owner/admin close is fenced and audited; both journal posting and reversal reject a closed current period. No period reopening or close checklist. |
| Contacts | Partial | Tenant-scoped customer/vendor create, list, search, detail read, edit and archive with roles, audit and duplicate protection; default list size is 50 with cursor paging. Phone, validated optional GSTIN and billing address are captured and editable. Organization identifiers, opening balances, exports and customer/vendor ledgers remain. |
| Products and services | Partial | Tenant-scoped catalog API and responsive create/search UI; safe integer paise, unique organization code, audit and archive. Units, tax categories and edit UI remain. |
| Sales invoices | Partial | Tax-free service drafts snapshot customer/service facts and optional due date; issuance assigns an India fiscal-year number and atomically posts AR against sales income with audit/idempotency. Due balances accept partial receipts and partial credit notes; each credit note atomically reduces sales income and AR, is immutable, audited and idempotent, and cannot exceed the unpaid balance. Aging, control reconciliation and print views include credits. GST, discounts, inventory/COGS and richer PDF templates remain. |
| Purchases and expenses | Partial | Vendor bill drafts validate active same-tenant vendors and expense accounts; posting is human-confirmed, idempotent and atomic with immutable bill facts, audit, and expense debit/payables credit. Vendor payments support partial/final allocation. Vendor credit notes debit AP and credit the selected expense account, are immutable/audited/idempotent, cannot exceed unpaid bill balances, and adjust later payment eligibility. Tax/inventory bills and attachments remain. |
| Receipts, payments and banking | Partial | Customer receipts and vendor payments can be allocated partially or fully to issued invoices/posted bills with cash/bank accounts, outstanding-balance checks, tenant/role fences, idempotency, audit and atomic control-account journals. Credit notes reduce both receivable and payable subledgers and reconcile to their documents; they are not cash refunds. Bank statements now support signed integer-paise CSV imports with duplicate fingerprints, journal matching without implicit posting, and audited reconciliation guarded by opening/closing ledger balances, unmatched-line checks and non-overlapping periods. Web Banking workflow is connected and mobile-width E2E verified. Advances, refunds and transfers remain. |
| General ledger and reports | Partial | Tenant-scoped general ledger with India-local date filters, normal-side running balance and cursor pagination; trial balance reconciles debit/credit; fiscal-year P&L and balance sheet include current earnings. Aged receivables/payables summarize outstanding amounts in date buckets and exclude settled documents. Accounts-receivable and accounts-payable control balances are compared against open invoice/bill balances with difference indicators. Formula-safe CSV exports cover trial balance, P&L, balance sheet, aging and loaded ledger rows. A date-filtered dashboard now derives revenue/expenses from period journals and cash, receivables, payables from ledger balances through the end date, and shows recent posted activity. First Mongo CI run caught a cash-fixture account-code mismatch; fixture is corrected locally but awaits CI rerun. Complete multi-page ledger exports remain. |
| GST | Missing | No GST-specific invoice, product tax category, place-of-supply, tax-component or rate configuration structures yet. No reviewed calculation/rate rules. Do not claim GST compliance. |
| AI assistance | Missing | No draft/explain/review workflow. Any future AI must require explicit human approval before posting. |
| Browser/mobile | Partial | Responsive web shell and auth/onboarding, dashboard, account, opening balance, contact, product, invoice, receipt, bill, payment and bank workflows. Playwright covers sign-up, financial vertical slices and bank import/matching/reconciliation at 390px; contact edit and dashboard assertions are added but await execution against an available local API/database. There is no mobile app workspace. |
| Release operations | Missing | No verified staging, production monitoring, least-privilege runtime database role, backup/restore rehearsal or release checklist. |

The API server starts under Node after using runtime-safe Mongoose imports. Root lint checks `apps` and `packages`. Current local `pnpm typecheck`, `pnpm lint`, `pnpm build`, and `pnpm test` pass; `pnpm test` reports 21 passed and 67 MongoDB integration tests skipped because no local test replica is available.
