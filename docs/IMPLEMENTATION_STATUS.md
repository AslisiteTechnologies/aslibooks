# Implementation status

Status verified on 2026-11-04 from the local checkout `develop/phase-1-foundation`. This is an MVP in active development, not a production-ready release.

| Area | Status | Verified implementation and remaining gaps |
| --- | --- | --- |
| Authentication | Partial | Better Auth registration, login, session and logout have HTTP integration coverage. Password recovery, verified email, rate limits and session-expiry UX remain. |
| Organizations and membership | Partial | Authenticated organization create/list and membership-scoped access. Owner/admin company name, GSTIN format and pre-ledger fiscal-year settings are editable with transactional membership fencing and audit. Persistent switching, invitations, role administration and ownership transfer remain. |
| Chart of accounts | Partial | Tenant-scoped list/create/rename/archive API, responsive UI, membership write fence, audit, first-post serialization and legacy journal reference protection. Optional idempotent 23-account INR starter chart and explicit one-time balanced opening-balance journal are implemented; account grouping/normal balance metadata remain. |
| Journals | Partial | Authenticated tenant-scoped list/detail, manual posting and reversal endpoints; actor from session, role fences, idempotency, audit and fiscal period gate. MUI review-before-post workflow and reversal reason. Opening balances post through a separately audited source journal. General ledger aggregation, drafts and accounting exports remain. |
| Fiscal periods | Foundation implemented | Annual periods default to April–March; dates use Asia/Kolkata; first use creates the open period transactionally; owner/admin close is fenced and audited; both journal posting and reversal reject a closed current period. No period reopening or close checklist. |
| Contacts | Partial | Tenant-scoped customer/vendor create, list, search and archive with roles, audit and duplicate protection; default list size is 50 with cursor paging. Edit UI, identifiers, tax/address metadata, opening balances, exports and customer/vendor ledgers remain. |
| Products and services | Partial | Tenant-scoped catalog API and responsive create/search UI; safe integer paise, unique organization code, audit and archive. Units, tax categories and edit UI remain. |
| Sales invoices | Partial | Tax-free service drafts snapshot customer/service facts and optional due date; issuance assigns an India fiscal-year number and atomically posts AR against sales income with audit/idempotency. Overdue flags are derived from India-local dates; customer receipts can settle invoices; aging summaries reconcile to outstanding balances. GST, discounts, inventory/COGS, PDF and credit notes remain. |
| Purchases and expenses | Partial | Vendor bill drafts validate active same-tenant vendors and expense accounts; posting is human-confirmed, idempotent and atomic with immutable bill facts, audit, and expense debit/payables credit. Vendor payments now support partial/final allocation to posted bills, cash/bank credits, AP debits, audit, and replay protection. Tax/inventory bills, attachments and vendor credits remain. |
| Receipts, payments and banking | Partial | Customer receipts and vendor payments can be allocated partially or fully to issued invoices/posted bills with cash/bank accounts, outstanding-balance checks, tenant/role fences, idempotency, audit and atomic control-account journals. Advances, refunds, transfers, imports and reconciliation remain. |
| General ledger and reports | Partial | Tenant-scoped general ledger with India-local date filters, normal-side running balance and cursor pagination; trial balance reconciles debit/credit; fiscal-year P&L and balance sheet include current earnings. Aged receivables/payables summarize outstanding amounts in date buckets and exclude settled documents. Connected reports screen. Exports and data-backed dashboard remain. |
| GST | Missing | No reviewed calculation/rate rules. Do not claim GST compliance. |
| AI assistance | Missing | No draft/explain/review workflow. Any future AI must require explicit human approval before posting. |
| Browser/mobile | Partial | Responsive web shell and auth/onboarding, account, opening balance, contact, product, invoice, receipt, bill and payment screens. Playwright flow exercises opening entries, customer/vendor setup, invoice issue/receipt settlement, bill draft/post/partial/final payments, manual journals and reconciled reports at 390px; there is no mobile app workspace. |
| Release operations | Missing | No verified staging, production monitoring, least-privilege runtime database role, backup/restore rehearsal or release checklist. |

The API server starts under Node after using runtime-safe Mongoose imports. Root lint checks `apps` and `packages`. The master vision file supplied by the user is untracked user content and must be preserved.
