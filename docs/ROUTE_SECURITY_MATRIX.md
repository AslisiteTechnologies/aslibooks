# API Route Security Matrix

Reviewed against `apps/api/src/index.ts`, `apps/api/src/routes/organizations.ts`, each mounted router declaration, and current route integration suites on 2026-11-05. Every `/api/organizations` request requires a verified Better Auth session. Organization business writes also pass the trusted-Origin middleware. This is a source-and-test inventory, not a claim that every permutation has exhaustive negative coverage.

## Evidence and remaining audit work

- Direct tests now cover foreign organization IDs and role denials for the principal ledger, document, bank, attachment, report and membership route families. Positive accountant cases include catalog writes, invoices, bills, credits, receipts/payments, advances, bank workflows, journals and reversals. Fiscal close is allowed to owner/admin and denied to accountant/viewer.
- The browser tests exercise the end-to-end accounting journey, tenant switching/isolation, report printing, contact-statement CSV export and narrow viewport navigation. CSV is generated in the browser from an authorized tenant statement; the API has no general file-export endpoint.
- The evidence is not exhaustive for every endpoint × role × guessed object identifier × concurrency combination. Continue adding targeted no-side-effect cases when reviewing uncovered references. Membership write fencing is verified for ledger posting and organization management but should be rechecked whenever a new mutating route is added.
- Application Mongoose guards cannot prevent a privileged raw database client or administrator from changing journal or audit records. Production database grants, restore, monitoring, malware scanning, retention and a qualified GST/accounting review remain external gates and are not evidenced by these route tests.
